# LWA-Web MCP: evidence-preserving design

**Status:** implementation contract with one [offline agent pilot](../results/experiment-03/offline-agent-pilot-run-20261021/report.md), not a validated mitigation effect. This specifies how the current [MCP wrapper](../scripts/mcp_lite_extractor.py) should evolve. The four [local reproduction attempts](../results/reproduced-literature-gaps-synthesis-report.md) motivate the design but do not prove any mitigation works. The pilot used saved captures and has no matched baseline.

## One agent-facing workflow

An autonomous agent calls `inspect_web_evidence(target, question, mode="live")`. The tool acquires the page itself, selects relevant evidence, and returns structured observations. `mode="snapshot"` is an explicit offline mode that accepts a saved capture; a URL must never silently resolve to an old benchmark fixture. `inspect_evidence(capture_id, evidence_ids)` retrieves saved observations and bounded HTML excerpts. `inspect_image_crop(capture_id, image_sha256, bbox)` now returns bounded saved pixels as an MCP image with hash and original-image coordinates.

The first response must say whether it actually reached the requested content. It must not return a fabricated answer from a filename, a hard-coded campaign string, or an inaccessible challenge page. The agent should answer only from cited observation IDs or hash-bound image crops. The MCP server can constrain its own output, but cannot guarantee that every client agent obeys the contract; the offline pilot exposed wrong visual readings despite source citations.

## Mitigation contract

| Reproduced problem | Tool behavior | Offline acceptance check using existing artifacts |
| --- | --- | --- |
| Text extractors disagree; image text is absent from their union | Preserve a canonical rendered/visible text view and compare independent extractor views. Deduplicate by text **and source location**, retain disputed snippets with extractor provenance, then rank by the user's question. Inspect relevant image assets/crops with real Bangla/English OCR or vision; retain OCR confidence and crop reference. Do not inject ground-truth strings keyed to asset names. | Run the tool on saved Shwapno/Nagad captures. Show which selected facts each extractor exposed. `PUJA6`/`PUJA7` may be labeled `observed` only if OCR/vision actually read saved pixels; otherwise return `not_observed` with `image_unchecked` or `ocr_failed`. The five-text-extractor union alone must not be called a visual success. |
| API values differ from a saved HTML string search | Collect embedded JSON and, during browser acquisition, passive JSON responses generated by the page. Treat directly queried APIs as a separate source. Record product ID, variant, locale, request time, and whether a value appeared in the human-visible page. Never promote an internal field such as quantity sold into a claim about visible stock. If values conflict, return both with `conflicting` status. | For saved Shwapno HTML and the saved Algolia result, report exact-value nonmatches as `not_found_by_string_search`, not “absent from rendered page.” For Chaldal, identify `window.__serviceState` as embedded in the HTML. |
| Agents turn affordances or omissions into positive/negative claims | Emit claim-sized observations with evidence states. An enabled Buy button is `observed_affordance`; stock remains `unknown` unless an explicit stock statement supports it. A missing dropdown option is `not_observed_in_inspected_selector`, never physical incompatibility. `check_claim` checks literal quotations. `check_structured_claim` returns `supported`, `contradicted`, or `insufficient_evidence` for a narrow explicit, subject-bound captured text statement; it must not guess from unstated fields. | Use the saved Daraz stock/selector cases and Biman challenge. The structured response must not assert actual stock, incompatibility, or page absence from those inputs. The Biman result must be `access_blocked`, including when Chromium received a challenge page. |
| Saved references and live pages change with time | Attach capture time, acquisition method, URL/final URL, content hash, locale/variant, and per-observation source time. A snapshot result is explicitly historical; a current-value request requires fresh acquisition or returns `stale_or_unverified`. Compare versions only when the same item, variant, locale, and evidence surface are aligned. | Re-open the saved Shwapno capture in snapshot mode and check that it reports its historical provenance. The four Algolia values recorded in the Antigravity transcript are API observations, not proof of the follow-up homepage or the hand-coded 30% drift labels. |

## Observation schema

Return a compact JSON object; FastMCP can expose a Python dictionary as structured output. A future readable summary should be generated from the same object, not maintained independently.

```json
{
  "capture": {
    "id": "sha256-of-capture-manifest",
    "requested_url": "https://example.org/page",
    "final_url": "https://example.org/page",
    "mode": "live_http | live_browser | saved_snapshot",
    "captured_at_utc": "2026-10-21T00:00:00Z",
    "content_sha256": "...",
    "access": "ok | blocked | failed",
    "render_state": "initial_html | hydrated | unresolved"
  },
  "observations": [
    {
      "id": "obs-001",
      "subject": "product-123 / selected-variant",
      "predicate": "stock_status",
      "value": null,
      "state": "unknown",
      "evidence": ["dom:button-17"],
      "reason": "Purchase control observed; no explicit stock statement found in inspected scope"
    }
  ],
  "uninspected": ["variant-selector"],
  "resource_usage": {"acquisition_ms": 0, "processing_ms": 0, "input_bytes": 0, "output_bytes": 0}
}
```

Use `observed_positive`, `observed_negative`, `not_observed_in_scope`, `not_checked`, `unknown`, `conflicting`, `access_blocked`, and `stale_or_unverified` deliberately. `not_observed_in_scope` requires a named inspected scope; it is not a global negative. Each evidence ID must resolve to a DOM node/excerpt, embedded JSON path, network response, screenshot crop, or OCR result with coordinates and source hash. API-only fields carry `human_visible: false` or `human_visibility: unverified`.

## Acquisition and budget

1. Fetch HTTP with bounded response size and timeout. Detect access challenges before extracting text. Record redirect and status.
2. If the question remains unresolved and the page shows hydration/skeleton indicators, use one bounded browser capture. Wait for **question-relevant state** or a timeout, rather than treating `networkidle` as proof of hydration. Save rendered DOM, relevant network metadata, screenshot, and candidate image locations.
3. Rank DOM/JSON/image evidence by the question. Apply OCR to bounded, relevant crops; keep source geometry so a code or price remains attached to the correct card or banner. Do not OCR the entire full-page screenshot by default.
4. Stop after a declared time/byte/image budget and return the unresolved field and coverage limits. Report real measured time and bytes. Token count requires an actual tokenizer; `bytes / 4` is only a proxy and must not be named a measured token saving.

The server should preserve full captures locally while returning a bounded evidence list to the agent. Compression must occur after capture and source indexing so a short answer does not silently erase the only evidence for a fact. A browser or API can still be blocked; the correct result is a transparent access state, not a bypass claim.

## Remaining implementation order

1. Install or document a reproducible Tesseract runtime with English/Bangla data, then verify OCR on the saved image pixels. Crop retrieval now exists for saved images; add rendered image geometry and item/card binding so OCR text attaches to the correct visual subject. Fetching a referenced asset alone does not prove it appeared in the viewport.
2. Extend the browser collector from bounded DOM and passive JSON to question-relevant readiness and explicit state coverage. Keep API-only values separate from visible-page facts and report any conflict with aligned item, variant, locale, and time.
3. Expand the narrow subject-bound stock/compatibility checker beyond explicit English phrases only after item/variant binding and source visibility are reliable. Add per-call and per-session time/byte limits and measured tokenizer usage where the model/tokenizer is known.
4. Complete the [item-level adjudication worklist](../results/item-adjudication-worklist.csv) using saved captures and the [protocol](item-adjudication-protocol.md). The first [fresh-agent MCP run](../results/experiment-03/offline-agent-pilot-run-20261021/report.md) is descriptive; next compare the same agent on the same packet with a matched non-LWA tool condition and independently adjudicated references.

## Current implementation boundary

[`inspect_web_evidence`](../scripts/mcp_lite_extractor.py) calls the [evidence core](../scripts/lwa_evidence.py). It separates live HTTP, explicitly requested bounded Chromium rendering (`render="browser"`), and saved snapshots; records source hashes, time metadata, and unresolved states; detects recognizable challenge pages; compares available text-extractor outputs; searches embedded JSON and passively captured browser JSON with separate provenance; and never infers stock or compatibility from controls. With Tesseract and Bangla/English language data available, it can OCR **explicitly supplied local snapshot images** or up to three automatically fetched live-page raster references, including inline CSS backgrounds. Tesseract is absent from the system `PATH`; a user-local runtime enabled an [offline check](../results/offline-mcp-acceptance.md), but it did not recover exact Shwapno coupon codes. OCR lines are candidates with unverified exactness and cannot alone pass claim checks. [Local capture storage](../scripts/lwa_evidence_store.py) supports `inspect_evidence` and bounded `inspect_image_crop`; `check_claim` establishes exact non-OCR source quotations. `check_structured_claim` supports or contradicts only explicit English stock/compatibility phrases that contain the named subject in one captured HTML text node. It ignores OCR, JSON-only values, other subjects, Buy buttons, and missing options; its result describes a **captured statement**, not physical truth. Browser rendering is labeled unverified because its bounded text-stability wait cannot prove every lazy or interactive state loaded. The tool still lacks automatic viewport-to-asset geometry, external stylesheet background discovery, item/variant binding, general semantic adjudication, a session circuit breaker, tokenizer/billed-cost measurement, and a matched agent-level evaluation. The older `extract_web_page` fixture function remains importable for historical compatibility but is no longer registered as an agent-facing MCP tool.

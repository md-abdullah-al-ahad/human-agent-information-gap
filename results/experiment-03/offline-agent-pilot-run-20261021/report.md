# Offline LWA-Web agent pilot, 2026-10-21

The fresh Qwen/OpenCode agent matched **15 of 20 frozen reference answers** when using the LWA-Web MCP on saved captures. This is an end-to-end *offline* tool-use result, not evidence that LWA-Web improves accuracy over a matched baseline or works on today's sites. Two additional controls were excluded from the accuracy denominator: Biman's blocked capture was handled correctly; the download-count conflict task timed out.

## Run and audit trail

The [protocol](../../../docs/offline-agent-pilot-protocol.md) and immutable [gold manifest](../offline-agent-pilot-manifest.json) were prepared before agent execution. `prepare_offline_agent_pilot.py` rechecked 20 scored questions, two controls, and every source hash. The agent received only the answer-free packet at `/tmp/lwa-offline-agent-pilot-packet-20261021`; it was not given the gold or historical case reports. Each question had a fresh OpenCode v2.1.1 session using `openrouter/qwen/qwen3.8-27b`, temperature 0, a 180-second wall cap, and a 20-call MCP cap. The same English/Bangla user-local Tesseract runtime was enabled throughout. OpenCode's v2 Code Mode exposed the five LWA tools through `execute`; file, shell, browser, web search, and read permissions were denied, and the inherited Playwright MCP was disabled. The exact configuration and packet file hashes are in [run-spec.json](run-spec.json), [opencode-config.json](opencode-config.json), and [packet-hashes.json](packet-hashes.json).

The 22 session IDs, wall times, final text, and compressed raw event traces are indexed in [run-results.jsonl](run-results.jsonl); the [adjudication data](scored-results.json) contains each answer, reference, source-link status, and recorded tool metrics. The frozen gold was opened only after all 22 traces were saved. Five earlier setup preflights are preserved separately under `preflight/` and excluded: four lacked callable LWA tools, and one unrestricted probe used file/shell tools. The scored configuration was fixed before the first scored task.

The government answer conveys the broad idea of using once-fried oil in a vegetable dish, but it fails the preregistered `exact_key_phrase` rule because it does not say to strain the oil. The Shwapno abstention avoids an unsupported exact answer, yet its accompanying claim that no 7% coupon is present is contradicted by the saved pixels. A correct code string mentioned while denying the requested coupon does not count as an answer.

The Biman control returned `blocked` / `access_blocked` and did not invent flight facts. The 10 Minute School conflict control timed out without reporting the saved DOM's `5,00,000+` or explaining the mismatch with the older `৪,৫৮,৫৪৩+` reference. It therefore does not demonstrate temporal-conflict handling.

Across all 22 sessions, the traces record **122 nested calls** (maximum 15 in a single session), 22 distinct session IDs, and 1,405 seconds of wall time; the 20 scored tasks used 110 nested calls and 1,204 seconds. Three nested `fetch(file://...)` attempts failed with “fetch cannot be used for filesystem access.” No successful non-LWA nested tool call or live-web request appears in the scored traces. The nested-call count comes from OpenCode's `execute` metadata; the runner's live `tool_calls` field counted outer `execute` calls, so its 20-call stop was not a strict nested-MCP-call limiter. Post-run metadata confirms that every session nonetheless stayed under 20 nested calls. Two sessions hit the 180-second cap. The serialized tool payload in the event traces totals about 15.1 MB, including encoded image blocks and metadata; it is **not** a token count. OpenCode reports $0.13535 across the 22 sessions from its `step_finish.cost` fields; this is an OpenCode-reported figure, not an independently reconciled provider bill.

## What this establishes and what it does not

The pilot demonstrates that a fresh agent can call the real MCP, inspect bounded saved pixels, and answer many DOM and screenshot questions with source citations. It also exposes unresolved failures in exact visual transcription, entity identity, omission of a qualifying action, visual localization speed, and unresolved-reference handling. Passing the Biman control confirms access-state reporting for this saved challenge capture only.

This packet contains five scored sites and was selected from existing captures, with researcher-authored gold and no independent second adjudicator for every item. Some historical screenshots lack a precise acquisition time, and the testimonial crop was supplied directly, so that item tests reading rather than discovery. The setup denied ordinary file and web tools, but Code Mode still permitted attempted `fetch(file://...)`; also, the snapshot MCP accepted arbitrary local paths rather than enforcing a packet-root allowlist. The trace shows no gold access, but the isolation is not a hard filesystem sandbox. No matched Qwen baseline received the same packet without LWA, and older Playwright/Markdown runs differ in prompts, tool access, or references. Consequently 15/20 is a descriptive pilot result, not a causal mitigation effect or a replacement for the historical benchmark.

The next implementation target is evidence binding: constrain snapshot paths to an allowed root for blinded tests; attach each crop and OCR string to the correct visual card, subject, and percentage; improve orientation/localization so visual cases finish within budget; and add a final exact-value check that catches one-character promo-code and surname errors without converting uncertain OCR into false certainty. Then run a *matched* LWA-versus-baseline comparison with the same agent, captures, questions, budgets, and independent reference adjudication.
